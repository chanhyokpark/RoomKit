# React 직접 연결 장치 템플릿

[RoomKit 문서 홈](../../docs/TOC.md) · [Client 문서](../../docs/human/custom-devices.md)

브라우저가 Player 없이 `@roomkit/client`로 RoomKit 서버에 직접 연결되는 완성형 화면 장치 예제입니다. 웹사이트 이동, 구조화된 메시지, 트리거, 초기화와 BGM/SFX/대사/비디오 재생을 구현합니다.

## 설치하고 실행하기

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

`.env.local`에서 서버 URL, 장치 코드와 이름을 설정해 주세요. 장치 코드를 비워 두면 실행 화면에서 입력할 수 있으며 마지막 설정을 localStorage에 저장합니다. 이 예제는 여러 장치가 같은 브라우저 저장소를 공유해도 테스트 코드가 섞이지 않도록 Client의 `persistTestCode`를 끕니다.

## Studio에서 구성하기

1. 독립 화면용 장치 애셋을 만들고 코드를 지정해 주세요.
2. 오디오도 이 브라우저가 재생한다면 플레이어 애셋의 스피커와 스크린을 같은 장치로 지정해 주세요. 화면만 담당한다면 별도 스피커 장치를 지정해 주세요.
3. 프로덕션에서는 장치 애셋 코드를 `.env.local`에 넣어 주세요.
4. 테스트에서는 테스트 세션이 발급한 코드를 연결 화면에 입력해 주세요.

테스트 세션의 장치 코드는 Player 디버그 창의 장치 카드에서 복사하실 수 있습니다. MCP `create_session`도 테스트 장치 코드를 자동으로 발급합니다.

## 구현 범위

- `navigate` URL을 내부 iframe에 로드하고 `onLoad` 뒤 완료 응답을 보냅니다.
- BGM 반복/페이드, SFX·대사의 BGM ducking과 플레이스홀더 시간을 처리합니다.
- 대사 speaker/screen/both 역할, 라인 progress와 `holdBefore` 재개 신호, HTML/CSS 자막을 처리합니다.
- 비디오 frame, 실제 파일 완료/실패 응답과 플레이스홀더 타이머를 처리합니다.
- stop은 재생을 정상 완료시키고 reset은 전체 미디어·화면·힌트 코드를 초기화합니다.
- awaited 메시지 handler의 Promise가 끝난 뒤 Client가 자동으로 응답합니다.

프로젝트에 적용하실 때 `roomkit-device.ts`의 오디오 정책, 자동 재생 안내, 캐시와 접근성 UI를 운영 환경에 맞게 확장해 주세요. 브라우저 자동 재생 정책 때문에 최초 사용자 상호작용이 필요할 수 있습니다.

## 테스트하기

```sh
pnpm typecheck
pnpm build
```

테스트 세션에서 다음을 순서대로 확인해 주세요.

1. 연결 상태가 `connected`로 바뀌고 세션 상태가 갱신되는지 확인해 주세요.
2. 디버그 패널의 트리거가 이벤트를 실행하는지 확인해 주세요.
3. 웹사이트 이동 뒤 다음 커맨드가 iframe 로드까지 기다리는지 확인해 주세요.
4. 일반/반복 BGM, SFX, 실제·플레이스홀더 비디오를 재생하고 정지해 주세요.
5. 화면 전용 대사와 같은 장치 speaker+screen 대사를 각각 확인해 주세요.
6. 라인 사이 커맨드가 있는 대사가 커맨드 실행 후 다음 라인을 재생하는지 확인해 주세요.
7. 기다리는 메시지와 장치 초기화가 시퀀스를 멈추지 않는지 확인해 주세요.
8. 장치를 재시작했을 때 같은 프로덕션 코드로 다시 연결되는지 확인해 주세요.

## 배포하기

```sh
pnpm build
```

`dist/`를 정적 호스팅이나 키오스크 장치에 배포해 주세요. Client는 서버에 직접 연결하므로 이 프로젝트를 RoomKit의 웹사이트 애셋으로 등록할 필요가 없습니다. 환경변수는 빌드 시 코드에 포함되므로 민감한 관리자 정보는 절대 넣지 마세요. 장치 코드는 필요한 경우 실행 시 안전한 장치 설정 저장소에서 주입해 주세요.

만약 외부 호스팅을 사용한다면 배포된 사이트는 https를 사용해야 합니다.
