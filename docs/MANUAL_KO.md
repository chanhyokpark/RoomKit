# RoomKit — 사용자 매뉴얼

RoomKit은 방탈출 게임을 제작, 관리, 실행하기 위한 툴킷입니다. 제작자는 웹 **Studio**에서 게임(미디어, 장치, 이벤트로서의 퍼즐)을 구성하고, 운영자는 동일한 Studio에서 라이브 세션을 진행합니다. 방 내부에 설치된 장치(화면, 스피커, 키오스크, 센서)는 서버에서 실시간으로 푸시되는 커맨드를 **Player** 데스크톱 앱이나 `@roomkit/client` 라이브러리를 통해 실행합니다.

이 매뉴얼은 시스템 전체(개념, 설정, 제작, 운영, 클라이언트/헬퍼 통합 API)를 다룹니다. Studio와 Player의 UI는 한국어로 제공되며, UI 용어는 있는 그대로 인용되었습니다(예: **새 테마**, **세션 시작**). 초기 설계 결정 사항은 [SPEC.md](./SPEC.md)를 참고하십시오.

## 1. 개념 및 아키텍처

### 1.1 구성 요소

```
                 ┌──────────────────────────────────────────────┐
                 │              apps/server (NestJS)            │
   REST /api     │  auth · themes · assets · sessions · logs    │
  ┌─────────────▶│  runtime (sequence engine, timer, eval)      │
  │              │  gateway (Socket.io /device /admin /player)  │
  │              │  storage (S3 presign, zip import, sites)     │
  │              └──────┬───────────────┬───────────────────────┘
  │                     │               │
  │              Postgres (Prisma)   S3 / MinIO (media files)
  │
  │   Socket.io /admin ▲          Socket.io /device ▲   /player ▲
  │                    │                            │           │
┌─┴────────────────────┴─┐      ┌───────────────────┴───────────┴──────┐
│  apps/studio           │      │  apps/player (Tauri)                 │
│  SvelteKit SPA         │      │  launcher + stage windows            │
│  authoring + operation │      │  built on @roomkit/client            │
└────────────────────────┘      │  ┌────────────────────────────────┐  │
                                │  │ website iframe                 │  │
   any custom device ───────────┤  │ (@roomkit/helper, postMessage) │  │
   (@roomkit/client)            │  └────────────────────────────────┘  │
                                └──────────────────────────────────────┘
```

| 구성 요소         | 설명                                                                                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/server`     | NestJS 메인 서버: REST API(`/api` 접두사), Socket.io 게이트웨이 및 시퀀스 런타임(이벤트 엔진, 카운트다운 타이머, eval 샌드박스)을 담당합니다. Prisma를 통한 Postgres 연동, 미디어는 S3/MinIO에 저장합니다. |
| `apps/studio`     | 관리자용 SvelteKit SPA입니다. 테마별로 세 가지 워크스페이스가 있습니다: **애셋**(애셋 관리), **에디터**(이벤트/시퀀스 제작), **운영**(라이브 세션 운영).                                                   |
| `apps/player`     | 방 내부 장치용 Tauri 데스크톱 앱입니다. 런처 창에서 스테이지 창(장치당 1개)을 열어 오디오/비디오/자막을 재생하고 웹사이트를 임베드합니다.                                                                  |
| `@roomkit/client` | 커스텀 장치가 서버와 직접 Socket.io로 연결할 때 사용하는 TypeScript 라이브러리입니다. Player 앱도 이를 기반으로 제작되었습니다. 워크스페이스 전용 패키지입니다.                                            |
| `@roomkit/helper` | _Player의 iframe 내부에_ 표시되는 웹사이트에 임베드되는 아주 작은(~KB) 스크립트입니다. 서버와 직접 연결하지 않고 `postMessage`를 통해 Player와 통신합니다.                                                 |
| `@roomkit/shared` | 통신에 사용되는 모든 Zod 스키마(애셋 데이터, 커맨드, 프로토콜 이벤트, 헬퍼 엔벌로프)입니다. 서버/스튜디오/클라이언트 간의 단일 진실 공급원(SSOT) 역할을 합니다.                                            |

### 1.2 용어 정리

| 용어                                  | 의미                                                                                                                                                                                                                                                 |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Theme (테마)**                      | 하나의 방탈출 게임입니다. 모든 애셋, 페이즈, 이벤트, 세션은 정확히 하나의 테마에 속합니다. 복수 룸 운영이나 시즌 백업을 위해 테마를 복제(깊은 복사)할 수 있으며, zip으로 내보내거나 가져올 수 있습니다.                                              |
| **Asset (애셋)**                      | 테마 내에서 제작된 모든 객체입니다. 종류: 장치, 플레이어, BGM, 효과음, 대사, 비디오, 이미지, 파일, 웹사이트, 메시지, 힌트, 컴포넌트, 페이즈, 이벤트. 모든 애셋은 `이름`, `설명`, `태그`를 공유하며, 장치와 힌트는 테마 내에서 고유한 `코드`를 가집니다. |
| **Device (장치)**                     | 방 내부의 논리적 엔드포인트(화면, 스피커, 키오스크, 센서 브릿지 등)입니다. 접속 시 사용하는 `코드`로 식별됩니다. 장치를 **힌트 장치**로 지정하면 힌트 코드 입력 흐름을 실행할 수 있습니다.                                                           |
| **Player asset (플레이어)**           | 논리적인 *출력 그룹*입니다: 스피커 장치(오디오 재생) + 스크린 장치(자막/비디오 렌더링) + 자막 CSS로 구성됩니다. 재생 커맨드는 원시 장치가 아닌 이 '플레이어' 애셋을 대상으로 합니다. Player *앱*과 혼동하지 마십시오.                                |
| **Phase (페이즈)**                    | 순서가 있는 게임 진행 단계입니다. 실행 중인 세션은 항상 정확히 하나의 페이즈에 머물러 있습니다(테마가 공통 이벤트만 사용하는 경우 제외).                                                                                                             |
| **Event (이벤트)**                    | 게임 로직의 단위(트리거 + 커맨드 시퀀스)입니다. 특정 페이즈에 속하거나, **공통**(모든 페이즈에서 유효)으로 설정될 수 있습니다.                                                                                                                       |
| **Trigger (트리거)**                  | 이벤트를 시작하는 조건입니다: **장치 트리거**(장치가 이벤트 이름을 보고함), **수동 트리거**(운영자 버튼 클릭), **시스템 트리거**(세션 시작 `session:start`, 페이즈 시작 `phase:enter`, 페이즈 종료 `phase:leave`, 타이머 만료 `timer:expired`).      |
| **Sequence / Command (커맨드)**       | 이벤트에 저장되어 서버 런타임이 실행하는 명령어 목록입니다. 전체 커맨드 참조는 §4.4를 확인하십시오.                                                                                                                                                  |
| **Session (세션)**                    | 테마의 1회 라이브 실행입니다. `mode`는 **프로덕션**(테마당 동시 1개, 물리 장치가 코드를 통해 자동 연결됨) 또는 **테스트**(동시 여러 개, 운영자가 발급한 테스트 코드로 연결됨)가 있습니다. 상태 흐름: 시작 전 → 진행 중 ⇄ 일시정지 → 종료됨.          |
| **Hint (힌트)**                       | 코드(기본 4자리 숫자) + 순차적인 단계(HTML 텍스트, 선택적 이미지)로 구성됩니다. 플레이어가 힌트 장치에 코드를 입력하면 단계가 하나씩 공개됩니다.                                                                                                     |
| **Message (메시지)**                  | 장치로 구조화된 데이터를 보내기 위한 페이로드 _스키마_(타입이 지정된 필드)입니다. 실제 값은 **메시지 전송** 커맨드를 제작할 때 채워집니다.                                                                                                           |
| **Component (컴포넌트)**              | 장치 화면 위에 렌더링되는 재사용 가능한 커스텀 HTML/JS 오버레이입니다. 슬롯은 세 가지: 비디오 오버레이(예: 비디오 옆/위의 채팅 UI), 자막 렌더러, 힌트 코드 렌더러. 미디어 애셋(비디오/대사)에 붙이거나 플레이어/장치의 기본값으로 지정하며, 붙일 때마다 **속성 (props)** 값을 바꿔 끼울 수 있어 하나의 컴포넌트를 여러 애셋에서 재사용합니다. §4.6 참조. |
| **Tag (태그)**                        | 애셋 정리를 위한 색상 + 이름 라벨입니다. 필터링 용도로만 쓰이며 런타임에 영향을 주지 않습니다.                                                                                                                                                       |
| **Placeholder (플레이스홀더) 미디어** | 파일 없이 생성된 BGM/효과음/비디오 및 대사 애셋입니다. 설정된 재생 시간만큼 클라이언트가 재생을 시뮬레이션하므로, 실제 미디어 파일이 준비되기 전에도 시퀀스를 제작하고 테스트할 수 있습니다.                                                         |

### 1.3 게임 실행 방식 (End to End)

1. 제작자가 Studio에서 애셋과 이벤트를 작성합니다. 시퀀스는 서버에 저장됩니다.
2. 장치들이 장치 코드를 사용해 Socket.io `/device`로 연결하고 `welcome` 메시지를 받습니다.
3. 운영자가 세션을 시작합니다(**세션 시작**) — 타이머가 작동하고 `session:start` 이벤트가 발생한 후, 초기 페이즈에 대한 `phase:enter`가 발생합니다.
4. 장치가 트리거를 보고(`trigger`)하면, 서버는 일치하는 이벤트의 시퀀스를 실행하고 장치에 커맨드(play/stop/navigate/reset/message/hintCode)를 실시간으로 푸시합니다. **끝날 때까지 대기**가 설정된 커맨드는 장치가 응답(ack)할 때까지 시퀀스를 차단(block)합니다.
5. 운영자는 실시간으로 로그, 장치 상태, 실행 중인 이벤트를 모니터링하며, 수동 이벤트 트리거, 페이즈 전환, 타이머 조정, 힌트 전송을 할 수 있습니다.
6. **테마 종료** 커맨드가 판정(성공/실패)을 기록하고 세션을 종료합니다. 다음 팀이 오면 운영자는 새로운 세션을 시작합니다(필요 시 디바이스 일괄 초기화 진행).

명령어 전달은 최소 한 번 이상 보장(at-least-once)됩니다. 모든 커맨드는 UUID를 가지며, 응답(ack)받지 못한 커맨드는 재연결 시 재전송되고 클라이언트는 id로 중복을 제거합니다. 오프라인 상태인 장치로 인해 게임이 멈추지 않습니다(전송 실패로 로그가 남고 시퀀스는 계속 진행되며, 대기 중인 커맨드는 15분 후 타임아웃됩니다).

## 2. 시작하기

사전 요구 사항: Node ≥ 22, pnpm 10.x (루트 `package.json`에 `packageManager`로 고정됨), Docker (인프라용), 그리고 — Player 데스크톱 빌드 시에만 — Rust 툴체인(≥ 1.77.2).

### 2.1 인프라

개발 인프라는 docker compose(`docker-compose.yml`)를 사용합니다:

| 서비스      | 호스트 포트                       | 참고                                                                   |
| ----------- | --------------------------------- | ---------------------------------------------------------------------- |
| Postgres 17 | **5433**                          | user/password/db 모두 `roomkit` (e2e 테스트용 `roomkit_test`도 생성됨) |
| MinIO       | **9000** (S3), **9001** (console) | root `roomkit` / `roomkit123`; 버킷 `roomkit` 자동 생성됨              |

실행하는 두 가지 방법이 있습니다:

```sh
docker compose up     # 인프라만 실행(postgres + minio) — 호스트에서 dev 서버 실행 시
pnpm infra            # 또는 ./compose.sh — 서버 + 스튜디오를 포함한 전체 스택 실행
                      # (docker 프로필 "app"; 포그라운드 실행, Ctrl+C로 깔끔하게 종료)
```

`pnpm infra`는 설정이 필요 없는 가장 빠른 방법입니다: Docker 내에서 서버(3000포트)와 스튜디오(5173포트)를 빌드하고 실행하며, 기본 관리자 로그인 계정인 **`admin` / `roomkit`**을 제공합니다. 일상적인 개발 시에는 보통 `docker compose up`으로 인프라만 띄우고, 아래 설명처럼 호스트에서 개발 서버를 실행합니다.

> Docker 주의사항: 서버 코드를 변경한 경우 compose 내의 서버 이미지는 구버전 상태가 됩니다. 변경 사항이 왜 반영되지 않는지 고민하지 말고 `./compose.sh`를 재시작(빌드)하십시오.

### 2.2 서버 (Server)

`apps/server/.env.example`을 복사하여 `apps/server/.env`를 만듭니다. 기본값은 docker compose 환경과 일치하며, 반드시 설정해야 하는 항목은 다음과 같습니다:

- `DATABASE_URL` — `postgresql://roomkit:roomkit@localhost:5433/roomkit`
- `JWT_SECRET` — 16자 이상의 임의 문자열
- `ADMIN_ID` / `ADMIN_PASSWORD_HASH` — 단일 관리자 계정. 데이터베이스에 유저 테이블이나 시드가 없으며 계정은 완전히 env로 관리됩니다. bcrypt 해시 생성 방법:
  ```sh
  cd apps/server
  node -e "console.log(require('bcryptjs').hashSync(process.argv[1], 10))" 'yourpassword'
  ```
- `S3_ENDPOINT=http://localhost:9000`, `S3_REGION=us-east-1`, `S3_BUCKET=roomkit`, `S3_ACCESS_KEY_ID=roomkit`, `S3_SECRET_ACCESS_KEY=roomkit123`, `S3_FORCE_PATH_STYLE=true`
- `S3_PUBLIC_ENDPOINT` (선택 사항) — *브라우저/장치*가 사전 서명된(Presigned) URL을 사용할 때의 엔드포인트. 서버가 MinIO에 접근하는 경로와 다를 경우 설정합니다 (compose 환경: 내부 `http://minio:9000`, 공개 `http://localhost:9000`).
- `PUBLIC_SERVER_URL` (선택 사항) — 외부에서 접근 가능한 서버의 오리진(Origin). **웹사이트 이동** 커맨드에서 호스팅된 웹사이트의 URL을 생성할 때 사용됩니다 (기본값: `http://localhost:PORT`).

마이그레이션을 적용한 후 시작합니다:

```sh
pnpm --filter server exec prisma migrate deploy
pnpm dev:server        # @roomkit/shared 빌드 후, 3000포트에서 nest start --watch 실행
```

운영 환경: `pnpm --filter server build` 후 `pnpm --filter server start:prod` 실행. 모든 REST 라우트는 `/api` 접두사 아래에 있으며, `GET /api/health`는 공개된 활성 상태 확인(liveness check) 엔드포인트입니다.

### 2.3 스튜디오 (Studio)

```sh
pnpm --filter studio dev    # 5173포트에서 vite dev 서버 실행
```

서버가 `http://localhost:3000`에 있지 않은 경우, `apps/studio/.env`(`.env.example` 복사)에서 `PUBLIC_API_URL`을 설정하십시오(끝에 슬래시 없이 기본 서버 URL만 입력, `/api` 포함 안 함). 이 값은 빌드 시 인라인으로 처리됩니다. Studio는 CSR 전용 SPA이며, JWT는 `localStorage`에 보관되고 12시간 후 또는 인증 실패 시 만료되어 `/login`으로 돌아갑니다.

### 2.4 플레이어 (Player)

```sh
pnpm dev:player                 # tauri dev — 데스크톱 앱 실행, 프론트엔드는 5175포트
pnpm --filter player dev:web    # 브라우저 전용 테스트 환경 (Rust 불필요)
pnpm --filter player build:app  # 프로덕션 데스크톱 빌드 (tauri build)
```

브라우저 테스트 환경은 네이티브 애셋 캐시나 키오스크 잠금 기능이 없습니다 — 미디어는 사전 서명된 URL에서 스트리밍되며 설정 파일 대신 `localStorage`를 사용합니다. 5175포트는 고정되어 있습니다(스튜디오는 5173/5174 사용).

### 2.5 공유 패키지(Shared) 리빌드

`@roomkit/shared`는 서버에서 빌드된 `dist`를 사용하며, 스튜디오는 소스를 바로 참조(alias)합니다. 공유 스키마를 변경한 후에는 다시 빌드(`pnpm --filter @roomkit/shared build` — `pnpm dev:server` 실행 시 자동으로 수행됨)해야 서버와 타입이 갱신됩니다. 스키마에 필드를 추가할 때는 이전 클라이언트의 유효성 검사가 깨지지 않도록 `.default()`/`.optional()`을 사용하십시오.

## 3. 로그인 및 테마 관리

Studio → `/login`으로 접속합니다. 서버 환경 변수에 설정된 관리자 **아이디**와 **비밀번호**를 입력하고 **로그인**을 누릅니다.

사이드바 상단에는 테마 전환기가 있고, 아래에는 현재 테마의 세 가지 워크스페이스 **메뉴**인 **애셋**, **에디터**, **운영**이 있습니다. 제일 하단에는 **로그아웃**이 있습니다.

테마 전환기 버튼은 현재 테마와 제한 시간(**제한 시간 N분** 또는 **타이머 없음**)을 표시합니다. 드롭다운 메뉴 항목:

- **새 테마** — 생성. 필드: **이름**, **제한 시간 (분)** (카운트다운 타이머가 없으면 비워둡니다).
- **테마 수정** — 이름 변경 / 제한 시간 변경.
- **테마 복제** — 깊은 복사(Deep copy). 모든 애셋이 복제되며, 교차 참조(플레이어 장치 참조, 이벤트 페이즈, 시퀀스 타겟)는 복사본에 맞게 재매핑됩니다. 장치/힌트 코드는 그대로 복사됩니다(테마 내에서만 고유함). 미디어 파일은 새로 업로드되지 않고 원본과 공유됩니다. 복수 룸 운영이나 시즌 백업용으로 사용합니다.
- **테마 내보내기** — 테마(애셋 + 태그 + 미디어 파일)를 zip으로 다운로드합니다.
- **테마 가져오기** — 해당 zip 파일을 새로운 테마로 가져옵니다.
- **테마 삭제** — 테마와 **그에 속한 모든 애셋**을 영구적으로 삭제합니다(확인 대화상자: **취소** / **삭제**).

## 4. Studio에서 테마 만들기

일반적인 제작 순서: 장치 → 플레이어 → 미디어 → 웹사이트/메시지/힌트 → 페이즈 → 이벤트.

### 4.1 애셋 관리 (애셋)

애셋 페이지는 상단의 종류(Kind) 탭 영역, 아래의 애셋 목록, 그리고 선택한 애셋의 편집 패널로 구성됩니다.

- **종류 탭**, 그룹화(장치 · 미디어 · 콘텐츠 · 진행): **장치**, **플레이어** | **BGM**, **효과음**, **대사**, **비디오**, **이미지**, **파일** | **웹사이트**, **메시지**, **힌트**, **컴포넌트** | **페이즈**, **이벤트**.
- **태그 필터**(기본 **모든 태그**)로 목록을 좁힙니다. **태그 관리**에서 태그 대화상자를 열 수 있습니다(색상+이름으로 생성, 인라인으로 이름/색상 변경 및 삭제).
- **새 {종류}**(예: **새 BGM**, **새 대사**)로 애셋을 생성합니다. 모든 애셋 행/카드에는 **수정** 및 **삭제**가 있는 **⋯** 메뉴가 있습니다.
- 미디어 종류는 카드로 렌더링되며(BGM/효과음 카드는 인라인 재생 버튼 포함, 비디오는 미리보기를 엽니다), 기타 종류는 테이블(**이름**, **코드**, **정보**, **태그**)로 렌더링됩니다.
- 일괄 업로드가 가능한 종류의 경우 **ZIP 업로드** 버튼이 나타납니다 (자세한 내용은 §4.2 참조).

모든 종류가 공유하는 공통 폼 필드: **이름**(필수), **설명**(선택적 메모), **태그**, 그리고 장치/힌트의 경우 **코드**(힌트 코드 자리표시자: **비워 두면 4자리 자동 생성**). **저장** / **취소**를 눌러 적용합니다.

종류별 특수 필드:

| 종류                   | 필드                                                                                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **장치** (device)      | **코드**(테마 내 고유, 장치가 접속할 때 사용), **표시 이름**, **힌트 장치** 스위치(해당 장치가 힌트 코드 입력 UI를 실행함), **힌트 코드 컴포넌트**(`힌트 코드` 슬롯 컴포넌트가 코드 오버레이를 대신 렌더링; 설정 시 아래 CSS는 무시됨), **힌트 코드 CSS**(**힌트 코드 표시** 커맨드로 표시되는 기본 `.rk-hint-code` 오버레이 스타일링). |
| **플레이어** (player)  | **스피커 장치**, **스크린 장치**, **기본 자막 컴포넌트**(`자막` 슬롯 컴포넌트가 스크린 장치의 대사 자막을 렌더링; 대사 애셋에서 개별로 바꿀 수 있음), **자막 CSS**(컴포넌트가 없을 때 기본 `.rk-subtitle` 오버레이에 적용).                 |
| **BGM**                | **파일**, **재생 시간 (ms)**(파일이 없을 때의 플레이스홀더 지속 시간), **페이드 인 (ms)**, **페이드 아웃 (ms)**.                                                                                                                            |
| **효과음** (SFX)       | **파일**, **재생 시간 (ms)**.                                                                                                                                                                                                               |
| **비디오** (video)     | **파일**, **재생 시간 (ms)**, **전체 화면** 스위치 — 끄면 비디오 표시 영역을 **X/Y/너비/높이**(화면 대비 %, 미니 배치 미리보기 제공)로 지정, **비디오 컴포넌트**(`비디오` 슬롯 컴포넌트를 재생 중 화면에 오버레이 — 예: 작은 영상 옆의 채팅 UI). |
| **이미지** (image)     | **파일** — 웹사이트용 정적 리소스로 `/api/media/{assetId}`에서 공개 서빙됩니다. 파일이 없으면 설정한 비율의 생성된 플레이스홀더가 서빙됩니다.                                                                                               |
| **파일** (file)        | **파일** — 이미지의 임의 파일 버전, 동일한 공개 URL로 서빙됩니다.                                                                                                                                                                           |
| **대사** (dialogue)    | **재생 후 자막 유지** 스위치, **자막 컴포넌트**(이 대사에 한해 플레이어의 기본 자막 렌더링을 오버라이드; 비워 두면 플레이어 기본값), **라인 (재생 순서)** — 순서가 있는 대사 라인들(각 음성 파일, 재생 시간, **자막 (HTML 허용)** 포함). **라인 추가**로 덧붙입니다. |
| **웹사이트** (website) | **사이트 종류**: **외부 URL**(URL 등록) 또는 **ZIP 호스팅**(정적 사이트 zip 업로드 — 루트에 `index.html`이 있어야 하며, 감싸고 있는 단일 폴더는 자동 제거됨; 서버가 `/api/sites/{assetId}/`에서 서빙; **ZIP 재업로드**로 내용 원자적 교체). |
| **메시지** (message)   | **표시 이름**, **페이로드 스키마** — 키, 라벨, 타입(**문자열**/**숫자**/**불리언**/**JSON**), **필수 값** 필드들. 형태만 정의하며, 실제 값은 **메시지 전송** 커맨드에서 입력합니다.                                                         |
| **힌트** (hint)        | **코드**, **단계 (순서대로 공개)** — 각 단계는 HTML 텍스트(**힌트 내용 (HTML 허용)**) + 선택적 이미지로 구성됩니다. **단계 추가**로 덧붙입니다.                                                                                             |
| **컴포넌트** (component) | **슬롯**(**비디오**/**자막**/**힌트 코드**), **터치/클릭 받기**, **HTML**(인라인 `<style>`/`<script>` 포함 마크업), **속성 (props) 정의**, 그리고 라이브 **미리보기**. §4.6 참조.                                                          |
| **페이즈** (phase)     | **순서**(오름차순 진행 순서). 보통 에디터의 **페이즈 관리**에서 관리하는 것이 편합니다.                                                                                                                                                     |
| **이벤트** (event)     | 트리거 설정 + 시퀀스. 에디터에서 제작합니다 (§4.3 참조).                                                                                                                                                                                    |

미디어 파일은 사전 서명된 URL을 통해 S3로 직접 업로드됩니다(서버는 메타데이터만 처리). 파일을 비워두면 **플레이스홀더** 애셋이 생성됩니다. 이 경우 **재생 시간** ms 동안 재생을 시뮬레이션하므로 실제 미디어가 없어도 시퀀스를 테스트할 수 있습니다(플레이스홀더는 장치의 사전 캐싱 대상에서 제외됩니다).

### 4.2 ZIP 일괄 업로드

BGM/효과음/대사/비디오의 경우, **ZIP 업로드** 버튼을 사용해 zip 파일 안의 모든 미디어 파일을 파일명으로 된 새 애셋으로 한 번에 가져올 수 있습니다(항상 생성하며 중복 제거는 안 함). 파일명은 UTF-8이어야 하며, 불필요한 항목(`__MACOSX/`, dotfiles, 지원하지 않는 확장자)은 무시되고 결과로 보고됩니다.

대사(Dialogue) 그룹화: `이름_1.mp3`, `이름_2.mp3` 같이 끝나는 파일들은 `이름`이라는 하나의 대사 애셋으로 묶이며 접미사 숫자에 따라 라인 순서가 정해집니다. 접미사가 없는 파일은 한 줄짜리 대사가 됩니다. 자막은 이후 편집 화면에서 채워 넣습니다.

### 4.3 에디터 (에디터): 페이즈와 이벤트

에디터는 상단의 페이즈 탭(**공통**이 먼저, 그다음 각 페이즈; **페이즈 관리**에서 생성/이름변경/순서변경/삭제 가능 — 페이즈 삭제 시 해당 이벤트들은 공통으로 이동됨), 왼쪽의 이벤트 목록, 오른쪽의 시퀀스 에디터로 구성됩니다.

**새 이벤트**로 이벤트를 생성합니다. 메타데이터(**메타데이터 수정** 버튼):

- **페이즈** — 특정 페이즈 또는 **공통 (모든 페이즈)**. 세션의 _현재_ 페이즈 이벤트(및 공통 이벤트)만 실행될 수 있습니다. 페이즈가 맞지 않는 트리거는 무시되고 로그에 남습니다.
- **트리거 종류**:
  - **장치 트리거** — 장치가 `trigger`를 통해 **트리거 이름**(예: `door-open`)을 보고할 때 발생.
  - **수동 트리거** — 운영 화면에서 버튼으로만 발생.
  - **시스템 트리거** — **시스템 훅** 선택: **세션 시작**(`session:start`), **페이즈 시작**(`phase:enter`), **페이즈 종료**(`phase:leave`), **타이머 만료**(`timer:expired`). 페이즈 훅은 특정 페이즈에 속하며, 세션을 시작하면 초기 페이즈에 대한 '페이즈 시작'도 함께 발생합니다.
- **수동 실행 허용** — (트리거 종류에 상관없이) 운영 화면에 수동 실행 버튼을 표시합니다.
- **재진입 허용** — 이벤트가 이미 실행 중일 때 다시 트리거되는 것을 허용합니다(기본값은 차단). _서로 다른_ 이벤트들의 시퀀스는 항상 병렬로 실행됩니다.

시퀀스 에디터는 수직 형태의 커맨드 스택입니다: **커맨드 팔레트**(검색 가능, 그룹: **재생** / **장치** / **흐름** / **타이머** / **운영**)에서 추가하고, 드래그하여 순서를 바꾸며, 행 메뉴(**위로**/**아래로**/**복제**/**삭제**)를 사용합니다. 수정 사항은 자동 저장됩니다(**저장됨** / **저장 중** / **저장 실패** + **재시도**). 끊어진 참조(**삭제된 애셋을 참조합니다**)나 누락된 파라미터(**입력하지 않은 항목이 있습니다**)가 있는 행은 경고를 표시합니다 — 런타임은 시퀀스를 실패 처리하지 않고, null이나 끊어진 참조가 있는 커맨드를 건너뛰고(로그 기록) 다음으로 진행합니다.

커맨드 내의 모든 애셋 드롭다운에는 인라인으로 애셋을 생성하고 선택하는 **새 {종류} 만들기** 옵션이 있습니다.

### 4.4 커맨드 참조

재생 관련 커맨드는 **플레이어** 애셋(스피커/스크린 쌍)을 대상으로 하며, 장치 커맨드는 **장치**를 대상으로 합니다.

| 커맨드 (팔레트 이름) | 그룹   | 파라미터                                    | 동작                                                                                                                                                                             |
| -------------------- | ------ | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **대사 재생**        | 재생   | 대사, 플레이어, **끝날 때까지 대기**        | 음성은 스피커 장치로, 자막(줄 단위)은 스크린 장치로 전송. 렌더링 우선순위: 대사의 자막 컴포넌트 → 플레이어의 기본 자막 컴포넌트 → 플레이어의 자막 CSS가 적용된 기본 오버레이. 줄 타이밍은 스피커의 진행 상태 릴레이를 통해 동기화됩니다. |
| **대사 정지**        | 재생   | 플레이어, **모든 플레이어**                 | 특정 플레이어 또는 모든 플레이어의 대사를 정지합니다.                                                                                                                            |
| **효과음 재생**      | 재생   | 효과음, 플레이어                            | Fire-and-forget SFX (BGM/대사와 믹스됨).                                                                                                                                         |
| **효과음 정지**      | 재생   | 플레이어, **모든 플레이어**                 |                                                                                                                                                                                  |
| **비디오 재생**      | 재생   | 비디오, 플레이어, **끝날 때까지 대기**      | 스크린 장치에서 재생됩니다 — 전체 화면 또는 비디오 애셋에 설정한 위치/크기로 표시되며, 애셋에 붙인 비디오 컴포넌트가 있으면 재생 동안 함께 오버레이됩니다.                       |
| **비디오 정지**      | 재생   | 플레이어, **모든 플레이어**                 |                                                                                                                                                                                  |
| **BGM 재생**         | 재생   | BGM, 플레이어, **반복 재생**                | BGM *애셋*에 설정된 페이드 인/아웃 설정을 따릅니다. 반복 재생되는 BGM은 시작 즉시 응답(ack)을 보내므로 시퀀스를 차단하지 않습니다.                                               |
| **BGM 정지**         | 재생   | 플레이어, **모든 플레이어**                 | 애셋의 페이드 아웃 설정을 적용하여 정지합니다.                                                                                                                                   |
| **장치 리셋**        | 장치   | 장치                                        | `reset` 전송 — 장치가 초기 상태로 돌아갑니다(Player: 모든 재생 중지, 스테이지 초기화).                                                                                           |
| **모든 장치 리셋**   | 장치   | —                                           | 세션 내의 모든 장치를 리셋합니다.                                                                                                                                                |
| **웹사이트 이동**    | 장치   | 장치, 웹사이트                              | 장치를 해당 웹사이트로 이동시킵니다(Player: 스테이지 iframe에 표시). 사이트가 실제로 로드된 후에 장치가 응답(ack)하므로, 다음 커맨드는 사이트가 준비되었다고 가정할 수 있습니다. |
| **메시지 전송**      | 장치   | 장치, 메시지, 값(values)                    | 메시지 애셋의 필드 스키마에 따라 값을 입력하여 장치에 전송합니다(Player는 iframe 내의 헬퍼로 이 데이터를 전달합니다).                                                            |
| **힌트 코드 표시**   | 장치   | 힌트, 장치                                  | 장치에 힌트 입력 코드를 오버레이로 표시합니다 — 장치에 힌트 코드 컴포넌트가 설정되어 있으면 그 컴포넌트가, 아니면 힌트 코드 CSS가 적용된 기본 오버레이가 렌더링합니다.           |
| **힌트 코드 숨김**   | 장치   | 장치, **모든 장치**                         | 오버레이를 숨깁니다.                                                                                                                                                             |
| **대기**             | 흐름   | 시간 (ms)                                   | 서버 측 타이머입니다. 세션 일시정지 시 함께 멈춥니다.                                                                                                                            |
| **페이즈 전환**      | 흐름   | 페이즈                                      | 페이즈를 전환하고 leave/enter 훅을 실행합니다(leave 훅이 먼저 완료된 후 전환됨).                                                                                                 |
| **이벤트 호출**      | 흐름   | 이벤트, **끝날 때까지 대기**                | 다른 이벤트의 시퀀스를 실행합니다(재사용). 대기(waited)를 설정하지 않으면 완료를 기다리지 않습니다. 재귀 깊이는 8로 제한됩니다.                                                  |
| **JavaScript 실행**  | 흐름   | code                                        | 서버 샌드박스에서 실행됩니다 — §4.5 참조. `false`를 반환하면 시퀀스가 중지됩니다(가드/분기 역할).                                                                                |
| **테마 종료**        | 흐름   | **판정** (성공/실패)                        | 게임 종료: 모든 장치를 리셋하고, 판정을 기록하며(운영 화면에 표시됨), 세션을 종료합니다.                                                                                         |
| **타이머 조정**      | 타이머 | **동작**: 시간 조정 (±ms) / 일시정지 / 재개 | 카운트다운 타이머의 보너스/페널티 시간 부여 또는 일시정지/재개. 0 이하로 조정하면 만료(expired)됩니다.                                                                           |
| **알림 보내기**      | 운영   | 메시지                                      | 운영 화면에 토스트 알림을 띄웁니다(예: "3번 퍼즐 해결됨 — 문 확인").                                                                                                             |

### 4.5 Eval 샌드박스 (JavaScript 실행)

코드는 서버 측 `node:vm` 컨텍스트에서 동기적으로 실행되며 1초의 타임아웃 제한이 있습니다(무한 루프 방지 — eval 코드는 자막 HTML처럼 신뢰할 수 있는 관리자 입력으로 간주됨). 주입되는 `ctx` API:

```js
ctx.vars; // 세션 변수(get/set; 영속성 유지, 병렬 실행 간 공유)
ctx.phase; // 현재 페이즈 이름, 또는 null (읽기 전용)
ctx.trigger(name); // 이벤트 발생 (장치 트리거와 동일한 승인 규칙 적용)
ctx.log(msg); // 세션 로그에 기록
ctx.switchPhase(name); // 큐에 등록: 스크립트 반환 후 실행
ctx.notify(msg); // 큐에 등록: 운영 화면에 토스트 알림
ctx.adjustTimer(x); // 큐에 등록: 숫자(±ms) 또는 'pause' / 'resume'
ctx.endTheme(v); // 큐에 등록: 'success' | 'fail'
```

큐에 등록되는 동작(Queued actions)은 즉시 인자를 검증하지만(잘못된 인자는 예외를 던지고 시퀀스를 중지시킴), 실행 자체는 스크립트가 반환된 후 호출 순서대로 이루어집니다. `return false`는 시퀀스를 중지시킵니다(일반적인 가드 패턴):

```js
// 팀이 3개의 열쇠를 모두 찾았을 때만 진행
ctx.vars.keys = (ctx.vars.keys ?? 0) + 1;
if (ctx.vars.keys < 3) return false;
ctx.notify("모든 열쇠 발견!");
```

### 4.6 커스텀 컴포넌트 (컴포넌트)

기본 오버레이의 CSS만으로 부족할 때 — 작은 영상이 구석에서 재생되는 동안 화면을 채우는 채팅 화면, 애니메이션 자막, 테마에 맞춘 힌트 코드 배지 — **컴포넌트** 애셋을 만듭니다. 인라인 `<style>`/`<script>`를 포함한 HTML 문서로, 장치가 스테이지 위에 샌드박스 iframe으로 렌더링합니다.

컴포넌트는 한 번 만들어 여러 곳에서 재사용합니다: **슬롯**(붙일 수 있는 위치)과 선택적 **속성 (props)**을 선언하고, 붙이는 쪽에서 속성 값을 채웁니다.

| 슬롯 | 붙이는 곳 | 대체 대상 |
|---|---|---|
| **비디오** | 비디오 애셋 (**비디오 컴포넌트**) | 없음 — 해당 비디오가 재생되는 동안 화면에 오버레이 |
| **자막** | 대사 애셋 (**자막 컴포넌트**) 또는 플레이어 (**기본 자막 컴포넌트**) | 기본 `.rk-subtitle` 오버레이 + 자막 CSS |
| **힌트 코드** | 장치 (**힌트 코드 컴포넌트**) | 기본 `.rk-hint-code` 오버레이 + 힌트 코드 CSS |

폼 필드:

- **슬롯** — 나중에 바꾸면 이전 슬롯에 붙어 있던 곳은 기본 렌더링으로 되돌아갑니다(깨졌거나 슬롯이 맞지 않는 참조가 재생을 중단시키는 일은 없습니다 — 장치는 그냥 기본으로 폴백합니다).
- **터치/클릭 받기** — iframe이 화면 전체를 덮으므로, 기본은 **꺼짐**(터치가 아래 웹사이트로 통과)입니다. 컴포넌트 자체에 조작 UI가 있을 때만 켜세요.
- **HTML** — 문서 본문입니다. 이미지/파일 애셋은 `RoomKit.mediaUrl('<애셋 ID>')`로 참조합니다.
- **속성 (props) 정의** — 타입이 지정된 필드(메시지 스키마와 같은 에디터)입니다. 붙일 때마다 값을 따로 넣을 수 있어, 예를 들어 하나의 채팅 스킨 컴포넌트로 비디오마다 다른 상대방 이름을 보여줄 수 있습니다.
- **미리보기** — Player와 동일한 방식(동일한 iframe 호스트)으로 렌더링되는 라이브 미리보기입니다. 화면비 프리셋(16:9/4:3/9:16), **새로고침**, 테스트 속성 값, 그리고 슬롯별 **테스트 이벤트** 컨트롤(비디오 타임라인 스크러버, 자막 표시, 힌트 코드 표시, **메시지 전송** 테스터)을 제공합니다.

iframe 내부에는 브리지 SDK가 `window.RoomKit`으로 미리 로드되어 있습니다:

```js
RoomKit.props                      // 이 부착 지점의 속성 값
RoomKit.slot                       // 'video' | 'subtitle' | 'hintCode'
RoomKit.mediaUrl(assetId)          // 이미지/파일 애셋의 공개 URL
RoomKit.on('init', (props) => {})  // 속성 준비 완료 (이미 준비됐으면 즉시 발생)

// 슬롯 이벤트
RoomKit.on('video',    ({ status, currentTimeMs, durationMs }) => {}) // 비디오 슬롯; 초당 ~5회
RoomKit.on('subtitle', ({ html, lineIndex, lineCount }) => {})        // 자막 슬롯, 줄마다
RoomKit.on('hintCode', ({ code }) => {})                              // 힌트 코드 슬롯

// 마운트된 모든 컴포넌트는 '메시지 전송' 페이로드도 수신합니다
RoomKit.on('message', ({ messageId, messageName, payload }) => {})
```

비디오 시간과 실시간 메시지로 구동되는 최소한의 채팅 화면 예시:

```html
<div id="chat"></div>
<style>
  #chat { position: absolute; right: 0; width: 40%; height: 100%; background: #111; color: #eee; }
  .bubble { margin: 8px; padding: 8px 12px; background: #333; border-radius: 12px; }
</style>
<script>
  const bubbles = [ { at: 3000, text: '어디야?' }, { at: 8000, text: '빨리 와…' } ];
  function add(text) {
    const el = document.createElement('div');
    el.className = 'bubble';
    el.textContent = text;
    document.getElementById('chat').appendChild(el);
  }
  RoomKit.on('init', (props) => { if (props.title) add(props.title); });
  RoomKit.on('video', ({ currentTimeMs }) => {
    while (bubbles.length && bubbles[0].at <= currentTimeMs) add(bubbles.shift().text);
  });
  RoomKit.on('message', ({ messageName, payload }) => {
    if (messageName === 'chat') add(payload.text);   // 시퀀스에서 실시간으로 푸시
  });
</script>
```

이 컴포넌트를 비디오 애셋에 붙이고, 비디오의 **전체 화면**을 끈 뒤 화면 왼쪽 60% 영역으로 위치를 지정하면 — 나머지 공간을 채팅이 채웁니다. `message` 이벤트는 메시지 애셋 + **메시지 전송** 커맨드와 자연스럽게 짝을 이루어, 원하는 타이밍에 콘텐츠를 밀어넣을 수 있습니다.

컴포넌트는 (자막 HTML처럼) 신뢰할 수 있는 관리자 입력으로 간주됩니다. iframe 샌드박스는 장애 격리를 위한 것입니다 — 스크립트 오류가 나도 해당 컴포넌트만 깨질 뿐, 스테이지는 멀쩡합니다.

## 5. 테마 테스트 및 운영

모든 라이브 작업은 **운영** 워크스페이스에서 이루어집니다: 왼쪽은 세션 목록, 오른쪽은 선택된 세션의 대시보드입니다.

### 5.1 세션

- **프로덕션 세션 만들기** — 대기 중인 프로덕션 세션을 생성합니다. 테마당 종료되지 않은 프로덕션 세션은 1개만 존재할 수 있습니다. 장치 코드가 테마의 장치 애셋 코드와 일치하는 물리적 장치들은 자동으로 연결됩니다 — 세션이 생성되기 *전*이더라도 장치들은 로비에서 대기하다가 세션이 생성되는 즉시 연결됩니다.
- **테스트 세션 만들기** — 동시에 여러 개를 실행할 수 있습니다. 대화상자에는 두 개의 탭이 있습니다:
  - **연결된 플레이어** — 서버에 등록된(**플레이어 이름**으로 식별되는) Player 앱을 선택합니다. 장치별로 테스트 코드가 자동 생성되며 Player의 런처가 모든 스테이지 창을 자동으로 엽니다. 비어 있는 경우: Player 앱을 먼저 실행하고 서버에 연결하십시오.
  - **직접 입력** — 장치별로 테스트 코드(숫자 0/1, 알파벳 l/o를 제외한 영문 6자리)를 직접 입력합니다. 폼은 이전 입력값을 자동 제안합니다(테마별로 저장됨). 이 코드를 아무 클라이언트(Player 런처 항목, `@roomkit/client` 사용자 등)에 전달하여 접속시킵니다. 세션이 종료되면 코드는 해제됩니다.
- 세션은 **대기**(**시작 전**) 상태로 생성됩니다 — 장치들이 미리 연결될 수 있으므로, 시작 전에 오프라인/온라인 상태를 검증할 수 있습니다.
- **세션 시작**을 누르면 확인 대화상자(**세션을 시작할까요?**)가 열립니다: 오프라인 장치가 있으면 경고(**오프라인 장치가 있습니다:** — 무시하려면 **그래도 시작**)하며, **시작 전 모든 디바이스 초기화** 옵션을 제공합니다. 시작하면 타이머가 작동하고 '세션 시작' 훅과 초기 '페이즈 시작' 훅이 발생합니다.
- **일시정지** / **재개**는 세션 전체를 일시정지합니다(타이머, 대기 커맨드, 재생 상태 브로드캐스트 포함). **세션 종료**는 실행 중인 모든 시퀀스를 중단하고 장치의 연결을 해제하며 테스트 코드를 회수합니다; 종료된 세션은 다시 시작할 수 없습니다. 생성 상태나 종료된 세션은 삭제할 수 있습니다(**세션 삭제** — 로그도 함께 삭제됨).

### 5.2 대시보드 카드

- **타이머** — 카운트다운 뱃지(**시작 전** / **일시정지** / **시간 초과**), 조정 버튼 **-5분 / -1분 / +1분 / +5분**, 그리고 **일시정지**/**재개** (세션 일시정지와 별개로 작동). 제한 시간이 없는 테마는 **타이머 없는 테마입니다.**라고 표시됩니다.
- **페이즈** — 현재 페이즈 표시, 다른 페이즈로 강제 **전환**(leave/enter 훅 실행, 확인창 뜸), 그리고 **재시작**(현재 페이즈의 leave + enter 훅 다시 발생).
- **수동 이벤트** — **수동 실행 허용**이 체크된 이벤트별로 하나의 버튼이 표시되며, **현재 페이즈** / **공통** / **다른 페이즈**로 그룹화됩니다(페이즈가 맞지 않는 버튼은 비활성화됨).
- **힌트 전송** — 힌트(`{코드} · {이름}`)와 단계를 선택하고 **전송**을 누르면 힌트 장치에 힌트가 푸시됩니다 — 운영자가 코드 입력 흐름을 건너뛰고 강제로 보여주는 기능입니다. 힌트 장치로 지정된 기기가 없으면 경고합니다.
- **디바이스** — 각 장치의 **온라인**/**오프라인** 상태(힌트 장치에는 **힌트** 뱃지 포함)와 **모든 디바이스 초기화**(일괄 리셋, 확인창 뜸) 버튼.
- **실행 중 이벤트** — 현재 진행 중인 시퀀스를 실시간으로 봅니다: 이벤트 이름, `현재/전체` 커맨드 위치, 실행 중인 커맨드 이름 표시.
- **테스트 코드** (테스트 세션 전용) — 발급된 코드와 **코드 복사** 버튼.
- **로그** — 실시간 세션 로그(종류: 세션/페이즈/타이머/트리거/이벤트/커맨드/eval/디바이스/힌트). 사후에 REST API로도 조회 가능합니다.

**알림 보내기** 커맨드의 토스트는 이 화면에 표시됩니다. 테마 종료 커맨드가 실행되면 대시보드에 판정 배너(**테마 종료 — 판정: 성공/실패**)가 나타납니다; 운영자가 세션을 직접 종료할 때까지 세션 자체는 라이브 상태를 유지합니다.

### 5.3 Player 앱으로 장치 실행하기

Player(RoomKit Player)는 항상 **런처** 창을 먼저 엽니다:

- **서버 URL** — 서버 오리진(예: `http://localhost:3000`). 자동으로 저장됩니다 (모든 설정은 앱 데이터 디렉토리의 `config.json`에 저장됨 — macOS 기준: `~/Library/Application Support/app.roomkit.player/`).
- **플레이어 이름** — Studio의 **연결된 플레이어** 탭에 나타날 이 기기의 이름과 실시간 연결 표시기(**서버에 연결됨** / **연결 중…** / **오프라인**). Studio가 이 플레이어를 타겟으로 테스트 세션을 시작하면 장치 창이 자동으로 열립니다.
- **디바이스** 목록 — 장치마다 행을 **추가**합니다: **라벨**, **디바이스 코드**(프로덕션 코드 또는 테스트 코드), **키오스크** 체크박스. **열기**는 해당 장치의 스테이지 창을 엽니다. **모두 열기**는 한 번에 전부 엽니다.

각 장치는 고유의 **스테이지 창**에서 실행되므로, 테스트를 위해 한 대의 PC에서 여러 장치를 돌릴 수 있습니다. 스테이지 창의 특징:

- 치명적 오류 발생 시 자동 재시도(retry-on-fatal): `invalid_code`나 `session_ended`가 클라이언트를 멈추게 하지 않고 5초마다 재폴링(re-poll)합니다. 따라서 룸 장치들은 세션(또는 테스트 코드)이 존재하기 전에도 전원을 켜 둘 수 있으며, 준비되는 즉시 알아서 연결됩니다.
- 미디어 사전 캐싱: 연결될 때마다 장치는 애셋 매니페스트를 가져와 로컬 캐시(`<앱 데이터 경로>/cache/`)에 파일을 다운로드합니다. 파일 키는 불변하므로 존재한다면 최신 파일입니다(매니페스트에 없는 파일은 정리됨). 캐시 누락 시 사전 서명된 URL에서 스트리밍하며 백그라운드에서 캐시를 채웁니다.
- 오디오(대사/BGM/효과음 동시 믹스), 비디오(전체 화면 또는 애셋에 설정한 위치/크기), 자막 오버레이, 힌트 코드 오버레이, 웹사이트(임베디드 iframe)를 재생/표시합니다. 컴포넌트(§4.6)는 스테이지 위에 샌드박스 iframe으로 마운트됩니다.
- 연결되지 _않았을 때만_ 연결 상태 배지를 표시합니다 — 프로덕션 룸에서는 어떠한 UI 크롬도 보이지 않습니다.

세션이 테스트 세션인 경우 자동으로 **테스트 모드**가 활성화됩니다. 상단 상태 표시줄에 **TEST** 태그, 장치 이름, 세션 상태(**대기**/**진행 중**/**일시정지**/**종료**), 타이머, 판정(**판정: 성공/실패**), 캐시 동기화 진행 상황, 연결 상태(접기 가능)가 표시됩니다. 추가 기능:

- **트리거** 입력란 — 이벤트 이름(예: `door-open`)을 입력하고 **전송**을 눌러 센서나 버튼을 시뮬레이션합니다. 최근 사용한 트리거는 재사용 가능한 칩 형태로 표시됩니다.
- 대기(waited) 중인 재생의 스킵 버튼: **대사 건너뛰기 ⏭** 및 **영상 건너뛰기 ⏭** — 미디어 재생을 멈추고 응답(ack)을 보내므로, `끝날 때까지 대기` 시퀀스가 즉시 넘어갑니다. 플레이스홀더 시뮬레이션도 건너뛸 수 있습니다.

**키오스크 모드**(**키오스크** 체크박스)는 프로덕션 룸 장치용입니다: 전체화면, 항상 위, 마우스 커서 숨김, 창 닫기 방지, 브라우저 단축키 억제(F5/F11/F12, Ctrl+R/W/P/F, 개발자 도구 단축키, 우클릭 메뉴). 탈출 단축키: **Ctrl+Shift+Alt+F12** → **키오스크 잠금을 해제할까요?** 확인창 뜸. OS 레벨 단축키(Win 키, Alt+Tab)는 앱에서 차단할 수 없습니다 — 하드웨어 레벨의 잠금이 필요하면 Windows 할당된 액세스(Assigned Access)를 사용하십시오.

### 5.4 최소 테스트 루프

1. 플레이스홀더 미디어 애셋 몇 개, 플레이어 1개, 페이즈 1개, 그리고 BGM을 재생하는 '세션 시작' 이벤트를 작성합니다.
2. Player 앱을 시작하고 서버 URL을 설정한 후 플레이어 이름을 확인합니다.
3. 운영에서: **테스트 세션 만들기** → **연결된 플레이어** → 해당 플레이어 선택 → **만들기**. 스테이지 창들이 자동으로 열립니다.
4. **세션 시작**. 로그 패널과 스테이지 창을 관찰하십시오. 테스트 오버레이의 트리거 입력란을 사용해 장치 트리거 이벤트를 발생시키고, 건너뛰기 버튼을 사용해 빨리감기를 테스트합니다.

## 6. Helper 스크립트로 웹사이트 만들기

(**웹사이트 이동** 커맨드를 통해) _Player의 iframe 내부에_ 표시되는 웹사이트는 `@roomkit/helper`를 임베드해야 합니다. 헬퍼는 자체 연결을 열지 않으며, 모든 트래픽은 `postMessage`를 통해 Player의 기존 장치 연결을 거쳐갑니다.

> 사이트가 독립적으로 실행되는 경우(일반 브라우저, 자체 기기), 그 자체로 별도의 장치입니다: 장치 애셋을 등록하고 헬퍼 대신 `@roomkit/client` (§7)를 직접 사용하십시오. 헬퍼는 Player 외부에서는 무용지물이며, 메시지는 아무데도 가지 않고 조용히 무시됩니다.

### 6.1 임베딩

패키지를 빌드(`pnpm --filter @roomkit/helper build`)하고 `packages/helper/dist/roomkit-helper.global.js`를 사이트에 복사합니다(이 스크립트는 `window.RoomKitHelper`를 정의하는 ~2.5 KB 용량의 독립적인 IIFE입니다):

```html
<script src="./roomkit-helper.global.js"></script>
<script>
  const rk = new RoomKitHelper();
</script>
```

객체가 생성될 때 헬퍼는 부모 창(Player)에 `hello`를 보냅니다. Player는 이 `hello`를 받을 때까지 발신 메시지들을 버퍼링하므로, 스크립트가 늦게 로드되더라도 메시지를 놓치지 않습니다.

또한 생성자는 iframe 안에 Player의 키오스크 기본값을 적용합니다: 문서 전체에서 우클릭 메뉴와 텍스트 선택이 비활성화됩니다(`input`/`textarea`는 선택 가능하게 유지). 일반 브라우저에서 사이트를 개발할 때는 `new RoomKitHelper({ lockdown: false })`로 건너뛸 수 있으며, `destroy()`가 원래대로 되돌립니다.

### 6.2 API

```js
const rk = new RoomKitHelper();

// 게임 이벤트 보고 — 트리거 이름이 일치하는 '장치 트리거' 이벤트를 실행시킵니다.
rk.trigger("door-open");
rk.trigger("keypad", { digits: "0417" }); // 선택적 JSON 페이로드

// 메시지 전송 커맨드의 페이로드 수신 (메시지 애셋의 필드 키를 사용한 값들)
rk.on("message", (payload, envelope) => {
  if (envelope.messageName === "set-lamp") lamp.toggle(payload.on);
});

// 힌트 UI (이 장치가 '힌트 장치'일 때만 의미 있음)
rk.submitHint("0417"); // 팀이 입력한 코드 제출
rk.requestHintStep(hintId, 1); // 다음 단계(0-based) 공개 요청
rk.on("hint", (hint) => {
  // { hintId, code, step, stepCount, textHtml, imageUrl }
  render(hint.textHtml, hint.imageUrl);
});
rk.on("hintError", (err) => {
  // err.reason: 'unknown_code' | 'unknown_hint' | 'invalid_step'
  //           | 'not_hint_device' | 'session_not_running'
});

// Player를 통해 남은 카운트다운 시간(ms) 가져오기 (null = 타이머 없는 테마;
// 일시정지 중에는 멈춤, 만료 시 0). Player가 응답하지 않으면 timeoutMs
// (기본 10초) 후 reject됩니다 — 예: 사이트가 Player 외부에서 실행될 때.
const ms = await rk.getRemainingTime();
await rk.getRemainingTime({ resync: true }); // 서버와 먼저 강제 재동기화 후 가져오기

rk.destroy(); // 리스너 제거; 이후 이 인스턴스는 더 이상 작동하지 않음
```

`on`/`off` 메서드는 체이닝(chainable)이 가능합니다. 이 API가 전부입니다 — 미디어 재생, 사이트 내비게이션, 장치 리셋은 iframe을 감싸고 있는 Player가 알아서 처리하므로, 웹사이트는 트리거, 메시지, 힌트 처리만 신경 쓰면 됩니다.

### 6.3 사이트 등록

웹사이트 애셋을 생성합니다(§4.1):

- **외부 URL** — 외부 어딘가에 호스팅된 사이트입니다. RoomKit은 단순히 해당 URL로 이동(navigate)만 합니다.
- **ZIP 호스팅** — 빌드된 정적 사이트를 업로드합니다(루트에 `index.html`이 있는 최대 500MiB 이하의 zip 파일). 서버가 S3에 압축을 풀고 `/api/sites/{assetId}/`에서 서빙합니다(공개 라우트입니다 — 유추 불가능한 asset id 자체가 일종의 키 역할을 하므로, 게임 사이트 내부에 중요한 기밀 정보를 넣지 마십시오). 다시 업로드하면 내용이 원자적으로 교체됩니다.

이후 **웹사이트 이동** 커맨드로 해당 애셋을 타겟팅합니다. 장치는 페이지가 로드된 후에 응답(ack)하므로, 다음 커맨드(예: 퍼즐을 소개하는 '대사 재생')는 사이트가 실제로 화면에 보인 후부터 시작됩니다.

## 7. @roomkit/client 직접 사용하기

`@roomkit/client`는 라즈베리 파이 소품 컨트롤러, 독립 실행형 키오스크 웹사이트, 모바일 앱 등 커스텀 장치가 Player 없이 서버와 직접 통신할 때 사용하는 라이브러리입니다. 워크스페이스 패키지(`workspace:*` 의존성, ESM + CJS)이며, Player 자체도 이를 기반으로 만들어졌으므로 Player의 동작이 곧 레퍼런스 구현입니다.

### 7.1 연결

```ts
import { RoomKitClient } from "@roomkit/client";

const rk = new RoomKitClient({
  serverUrl: "http://localhost:3000",
  deviceCode: "lab-door", // 프로덕션 장치 코드 또는 운영자가 발급한 테스트 코드
  deviceName: "door-controller", // 로그에 표시될 선택적 라벨
  retryOnFatalError: true, // invalid_code / session_ended 에러 발생 시에도 계속 재시도
});
rk.connect();
rk.on("status", (status, detail) => console.log(status, detail ?? ""));
rk.on("welcome", ({ device, session }) =>
  console.log("attached as", device.name),
);
```

옵션:

| 옵션                | 기본값         | 의미                                                                                                                                                                                                                                                    |
| ------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `serverUrl`         | —              | 서버 오리진 (http/https).                                                                                                                                                                                                                               |
| `deviceCode`        | —              | 프로덕션 장치 코드 또는 테스트 코드.                                                                                                                                                                                                                    |
| `deviceName`        | —              | 핸드셰이크용 선택적 라벨.                                                                                                                                                                                                                               |
| `persistTestCode`   | `true`         | 테스트 코드 연결 성공 시 (서버 오리진 기준으로) 스토리지에 기억해 두고 다음 `connect()` 때 우선 사용(자동 재접속). 여러 클라이언트가 동일 오리진의 localStorage를 공유하는 환경이라면 `false`로 설정하십시오(Player 창들이 이렇게 동작함).              |
| `storage`           | `localStorage` | `getItem/setItem/removeItem`을 지원하는 저장소; Node 환경에서는 무시(no-op).                                                                                                                                                                            |
| `retryOnFatalError` | `false`        | `invalid_code`나 `session_ended`는 기본적으로 상태를 `error`로 만들고 클라이언트를 중지시킵니다. 이 옵션을 켜면, 기억된 테스트 코드를 잊고 설정된 `deviceCode`로 `fatalRetryDelayMs` 주기마다 재폴링합니다. (세션/코드가 생성되기 전에 장치 부팅 가능). |
| `fatalRetryDelayMs` | `5000`         | 치명적 오류 발생 시 재시도 간격.                                                                                                                                                                                                                        |

연결 라이프사이클은 오직 `status` 이벤트와 `rk.status` getter를 통해서만 노출됩니다: `idle → connecting → connected / disconnected / error` (`detail`에 연결 에러 원인이 담깁니다). `rk.sessionState`는 마지막 세션 상태 스냅샷을 유지합니다.

### 7.2 커맨드 처리

재생 및 내비게이션은 *응답(ack)을 포함한 콜백*입니다: 서버 시퀀스가 여러분의 `done()` 호출을 기다리고 있을(blocked) 수 있으므로, 실제 작업이 끝난 후에 호출하십시오. `done()`은 멱등성(idempotent)을 가지며 커맨드 id로 중복 처리되므로 두 번 ack를 보낼 염려는 없습니다.

```ts
// 재생 — 라이브러리는 미디어를 직접 재생하지 않으며 여러분이 구현해야 합니다.
rk.on("play", (cmd, done) => {
  // cmd.channel: 'bgm' | 'sfx' | 'dialogue' | 'video'
  // 미디어 필드: fileKey/url (플레이스홀더인 경우 null) + durationMs (플레이스홀더 시간)
  if (cmd.url === null) return setTimeout(done, cmd.durationMs); // 플레이스홀더 처리
  const audio = new Audio(cmd.url);
  audio.onended = () => done(); // '끝날 때까지 대기'를 해제함
  audio.onerror = () => done("failed");
  audio.play();
});
rk.on("stop", (cmd) => stopChannel(cmd.channel, cmd.playerId)); // playerId가 null이면 전체 정지

// 내비게이션 — 사이트가 실제로 변경된 후에 ack를 보냅니다. 창 전체가 이동하는
// 환경이라면 location을 바꾸기 전에 done()을 먼저 호출하십시오(페이지가 곧 unload됨).
rk.on("navigate", (url, cmd, done) => {
  done();
  location.href = url;
});

// '메시지 전송'의 구조화된 페이로드
rk.on("message", (payload, cmd) => applyMessage(cmd.messageName, payload));

// '장치 리셋' / '모든 장치 리셋'
rk.on("reset", () => resetToInitialState());

// 세션 상태(페이즈, 일시정지, 타이머) — timerState === 'running'일 때
// timerRemainingMs를 기준으로 로컬 카운트다운을 진행합니다.
rk.on("sessionState", (s) => updateUi(s.state, s.phaseId, s.timerRemainingMs));
```

스피커와 스크린으로 나뉜 분리형 장치에서 대사를 처리하는 방법: 스피커 역할 기기가 각 줄이 시작될 때마다 `rk.sendProgress(cmd.id, lineIndex)`를 호출합니다; 스크린 역할 기기는 `rk.on('progress', …)`로 이를 수신하여 동기화된 상태로 자막을 전환합니다. (`role: 'both'`인 단일 클라이언트는 내부적으로 양쪽을 모두 처리합니다.)

### 7.3 트리거, 힌트, 사전 캐싱

```ts
// 센서나 버튼을 '장치 트리거' 이벤트에 연결
gpio.on("pressed", () => rk.trigger("door-open"));

// 힌트 UI — 이 기기가 '힌트 장치'일 때만 의미 있음
rk.submitHint("0417");
rk.requestHintStep(hintId, step + 1);
rk.on("hint", (hint) => renderHint(hint));
rk.on("hintError", (err) => flashError(err.reason));
rk.on("hintCode", (cmd) =>
  cmd.code ? showCodeOverlay(cmd.code, cmd.css) : hideCodeOverlay(),
);

// 남은 카운트다운 시간(ms), 마지막 세션 상태 스냅샷을 기준으로 로컬에서 계산됨
// (null = 타이머 없음; 일시정지 중에는 멈춤, 만료 시 0).
// resync 옵션은 먼저 서버에 최신 스냅샷을 요청합니다(연결이 끊어졌거나 타임아웃
// 시에는 로컬 값으로 대체(best-effort)).
const ms = await rk.getRemainingTime();
await rk.getRemainingTime({ resync: true });

// 사전 캐싱용 미디어 매니페스트 (사전 서명된 URL, 약 6시간 유효 — 갱신하려면 다시 호출)
const manifest = await rk.fetchAssetManifest();
for (const entry of manifest.entries) await download(entry.fileKey, entry.url);

rk.disconnect();
```

장치의 매니페스트에는 사전 캐시해야 할 내용만 포함됩니다: 스피커 장치에는 BGM/효과음/대사 라인이 포함되고, 스크린 장치에는 비디오가 포함됩니다. 플레이스홀더는 제외됩니다.

## 8. 참조 (Reference)

### 8.1 REST API

공개(public) 표시된 것을 제외한 모든 경로는 `/api` 접두사를 가지며 JWT Bearer 인증이 필요합니다. `POST /api/auth/login` `{ id, password }`를 호출하여 `{ accessToken }`을 발급받습니다.

| 영역             | 라우트 (Routes)                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 인증 (Auth)      | `POST /auth/login` (공개), `GET /auth/me`                                                                                                          |
| 상태 (Health)    | `GET /health` (공개)                                                                                                                               |
| 테마 (Themes)    | `GET/POST /themes`, `GET/PATCH/DELETE /themes/:id`, `POST /themes/:id/duplicate`, `GET /themes/:id/export` (zip), `POST /themes/import` (zip)      |
| 애셋 (Assets)    | `GET/POST /themes/:themeId/assets` (`kind`, `tagId` 쿼리), `GET/PATCH/DELETE /themes/:themeId/assets/:id`                                          |
| 태그 (Tags)      | `GET/POST /themes/:themeId/tags`, `PATCH/DELETE /themes/:themeId/tags/:id`                                                                         |
| 업로드 (Uploads) | `POST /themes/:themeId/uploads` (PUT 요청용 사전 서명 → `{ key, url }`), `GET /files/url?key=` (GET 요청용 사전 서명)                              |
| Zip 가져오기     | `POST /themes/:themeId/imports/:kind` (bgm/sfx/dialogue/video), `POST /themes/:themeId/imports/site`                                               |
| 호스팅된 사이트  | `GET /sites/:assetId/*` (공개)                                                                                                                     |
| 세션 (Sessions)  | `GET/POST /sessions`, `GET/DELETE /sessions/:id`, `POST /sessions/:id/start·pause·resume·end·timer·phase·phase/restart·trigger·reset-devices·hint` |
| 로그 (Logs)      | `GET /sessions/:id/logs`                                                                                                                           |

세션 *제어*는 REST로 이루어지며, `/admin` 소켓 네임스페이스는 브로드캐스트 전용입니다(세션 상태, 로그, 장치/플레이어 상태, 실행 중인 이벤트, 알림 등).

### 8.2 장치 통신 프로토콜 (socket.io `/device`)

`auth: { deviceCode, deviceName? }`으로 연결합니다. 서버→클라이언트: `welcome`, `command`, `session:state`, `hint:show`, `hint:error`, `progress`. 클라이언트→서버: `ack { commandId, status: done|failed }`, `trigger { event, payload? }`, `progress { commandId, lineIndex }`, `hint:submit { code }`, `hint:next { hintId, step }`, `assets:manifest`(요청/응답 방식). 통신 커맨드 타입: `play`(channel: bgm/sfx/dialogue/video), `stop`, `navigate`, `reset`, `message`, `hintCode`. 치명적 연결 오류: `invalid_code`, `session_ended`. 모든 스키마는 `packages/shared/src`(`protocol.ts`, `wire.ts`, `commands.ts`, `helper.ts`)에 정의되어 있습니다.

### 8.3 문제 해결 (Troubleshooting)

- **호스트 환경 개발 서버 로그인 실패** — `ADMIN_PASSWORD_HASH`가 설정되지 않았거나 올바른 bcrypt 해시가 아닙니다. §2.2의 한 줄짜리 스크립트로 해시를 생성하십시오. `admin`/`roomkit` 기본값은 docker-compose 스택 내에서만 적용됩니다.
- **장치에서 사전 서명된 업로드/재생 URL에 접근 불가** — `S3_PUBLIC_ENDPOINT`를 클라이언트가 접근 가능한 엔드포인트로 설정하십시오. 서명은 호스트 주소에 묶이기 때문에 내부 엔드포인트는 외부에서 작동하지 않습니다.
- **방 내부 장치에서 '웹사이트 이동' 커맨드가 localhost를 엶** — `PUBLIC_SERVER_URL`을 장치가 접근할 수 있는 서버의 오리진으로 설정하십시오.
- **`pnpm infra` 사용 시 서버 변경 사항이 반영되지 않음** — docker 이미지가 구버전입니다. `./compose.sh`를 재시작하여 다시 빌드하십시오.
- **공유 스키마(Shared schema) 변경 사항이 안 보임** — `@roomkit/shared`를 리빌드하십시오(서버는 `dist`를 참조합니다). 필드를 추가할 때는 `.default()`/`.optional()`로 설정하여 하위 호환성을 유지하십시오.
- **두 개의 Player 창이 동일한 장치로 연결됨** — 하나의 오리진을 공유하면서 직접 만든 클라이언트의 `persistTestCode`가 켜져 있는 경우 예상된 동작입니다. Player 자체는 설정 파일(config)에서 코드를 가져오고 `persistTestCode: false`로 설정되어 있습니다.
- **장치가 실행 중인데 상태가 오프라인으로 표시됨** — 코드(프로덕션 장치 애셋 코드 또는 발급된 테스트 코드)가 일치하는지 확인하십시오. 스테이지 창의 연결 배지에서 `connect_error` 원인을 확인하십시오.
- **E2E 테스트** — `pnpm test:e2e` (compose 초기화 스크립트가 생성한 `roomkit_test` 데이터베이스를 사용합니다).
