# 테스트하고 운영하기

[문서 홈](../TOC.md) · [이전: 테마 제작하기](./authoring.md)

## 테스트 방법 선택하기

빠른 방법부터 차례로 사용해 주세요.

1. Player가 없으면 AI/MCP의 **가상 장치**로 로직과 로그를 먼저 검증해 주세요.
2. 개발 중인 웹사이트는 **Player 테스트**의 웹사이트 URL 대체로 Helper 통신과 화면을 확인해 주세요.
3. **테스트 세션**으로 실제 이벤트, 타이머와 여러 장치를 함께 확인해 주세요.
4. 최종 단계에서 실제 Player와 방 안 장치로 타이밍과 음량을 확인해 주세요.

## Player 테스트

이전의 Studio **웹 테스트** 페이지는 제거되었습니다. 대신 Player 런처의 **테스트** 탭에서 관리자 계정으로 로그인해 테마, 장치와 웹사이트 URL 대체를 선택하면 실제 테스트 세션이 만들어지고 장치 창과 디버그 창이 함께 열립니다.

- URL 대체에 Vite 개발 서버 주소를 입력하면 세션 전체에서 해당 웹사이트 애셋 대신 개발 서버가 열립니다.
- 시뮬레이션이 아니라 실제 세션이므로 타이머, 페이즈, 트리거로 실행되는 이벤트와 힌트·정답 흐름을 그대로 확인할 수 있습니다.
- 디버그 창에서 세션·타이머·페이즈 제어, 수동 이벤트 실행, 장치별 이동·초기화·메시지·테스트 콜백, 수동 재생, 힌트 푸시와 실시간 로그를 사용할 수 있습니다.
- 장치별 테스트 코드를 복사하면 `@roomkit/client`로 직접 연결되는 개발 페이지도 같은 세션에서 시험할 수 있습니다.

자세한 사용 방법은 [Player 설정하기](./player.md#테스트-탭으로-테마-테스트하기)를 참고해 주세요.

## 테스트 세션

테스트 세션은 여러 개를 동시에 만들 수 있으며 세션별 장치 코드를 발급합니다.

- 연결된 Player를 선택하면 런처가 장치별 창을 자동으로 열 수 있습니다.
- 직접 입력을 선택하면 원하는 테스트 코드를 발급해 `@roomkit/client` 장치에 전달할 수 있습니다.
- 세션은 **시작 전** 상태로 만들어지므로 장치 연결을 먼저 확인하실 수 있습니다.
- 세션을 시작하면 타이머, `session:start`, 초기 `phase:enter` 이벤트가 실행됩니다.
- Player 테스트 탭에서 만든 세션은 모든 장치가 끊긴 뒤 60초(장치가 한 번도 연결되지 않았다면 생성 10분 뒤)에 자동으로 종료됩니다.

## 운영 화면

- 세션 상단의 **일시정지**는 타이머뿐 아니라 서버의 대기 커맨드와 새 트리거 처리를 함께 멈춥니다. **타이머** 카드의 일시정지는 게임 로직을 계속 실행하고 카운트다운만 멈춥니다.
- **타이머**에서 시간을 조정하거나 타이머만 일시정지할 수 있습니다.
- **페이즈**를 강제로 전환하거나 현재 페이즈를 재시작할 수 있습니다.
- **수동 이벤트**에서 허용된 이벤트를 실행할 수 있습니다.
- **디바이스** 카드에서 접속 상태와 현재 재생 중인 항목을 확인하고 정지할 수 있습니다.
- **실행 중 이벤트**에서 멈춘 시퀀스를 강제로 중단할 수 있습니다.
- **로그**에서 트리거, 커맨드, eval, 힌트와 장치 오류를 실시간으로 확인할 수 있습니다.

서버는 코드 입력 없이 힌트 단계를 보내는 운영 API를 제공하며 MCP의 `control_session`에서 `push_hint`로, 테스트 세션에서는 Player 디버그 창에서 사용할 수 있습니다. 현재 Studio 대시보드에는 이 버튼이 표시되지 않습니다.

Player, Client 또는 Helper가 Studio가 기대하는 버전보다 오래되면 운영 화면 위에 경고가 나타납니다. 연결되지 않았거나 버전을 보고하지 않은 구성 요소는 정확히 판별할 수 없으므로 배포한 버전도 함께 관리해 주세요.

## 로그 패널의 운영 콘솔

로그 패널 아래 입력란은 현재 세션에 일회성 커맨드를 보내는 운영 콘솔입니다. `help`로 명령 목록을, `list devices`, `list players`, `list events`, `list assets` 등으로 현재 이름과 상태를 확인해 주세요. 애셋은 UUID, 정확한 이름 또는 하나만 일치하는 부분 이름으로 지정할 수 있고, 공백이 있는 이름은 따옴표로 감싸 주세요.

```text
playBgm "로비 음악" once
playVideo 엔딩 메인스크린 wait
stopDialogue all
navigate 메인화면 인트로 lang=ko
adjustTimer +30s
notify "손님 응대가 필요합니다"
```

콘솔 커맨드는 이벤트 바깥에서 즉시 실행되며 입력과 결과 로그가 함께 표시됩니다. 세션이 시작되기 전이나 일시정지 중에도 운영자 오버라이드로 실행할 수 있으므로 프로덕션에서는 특히 주의해 주세요. 재생 정지는 기다리던 시퀀스를 정상 완료시키지만 이벤트 강제 종료는 남은 커맨드를 취소합니다.

페이즈 재시작은 현재 페이즈의 실행 중인 이벤트를 중단하고, 해당 페이즈에 속한 1회 이벤트 기록을 초기화한 뒤 leave/enter 훅을 다시 실행합니다. 공통 이벤트의 1회 기록은 초기화하지 않습니다.

## 실제 운영 흐름

1. 프로덕션 세션을 만들어 주세요. 테마 하나에는 종료되지 않은 프로덕션 세션을 하나만 만들 수 있습니다.
2. 장치가 모두 온라인인지 확인해 주세요.
3. 필요하면 **시작 전 모든 디바이스 초기화**를 선택하고 세션을 시작해 주세요.
4. 진행 중에는 로그, 페이즈, 타이머와 실행 중 이벤트를 확인해 주세요.
5. 테마 종료 커맨드 또는 운영자의 종료 동작으로 결과를 기록해 주세요.
6. 세션 결과에서 플레이 시간, 페이즈별 시간, 힌트·정답 사용, 일시정지와 운영 개입을 확인해 주세요.
7. 다음 팀을 받기 전에 모든 장치를 초기화하고 새 세션을 만들어 주세요.

## 완료 응답과 중단

재생 정지 버튼은 장치가 정상적으로 재생을 마친 것처럼 완료 응답을 보냅니다. 따라서 해당 미디어를 기다리던 시퀀스는 다음 커맨드로 진행합니다. 반면 **실행 중 이벤트 강제 종료**는 기다림을 취소하고 남은 커맨드를 실행하지 않습니다.

오프라인 장치로 보내는 커맨드는 실패 로그를 남기고 즉시 다음으로 진행합니다. 온라인 장치가 완료 응답을 보내지 않으면 기다리는 시퀀스가 멈출 수 있으므로 실행 중 이벤트 카드와 로그를 함께 확인해 주세요.
