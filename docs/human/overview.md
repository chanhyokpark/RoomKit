# RoomKit 이해하기

[문서 홈](../TOC.md)

RoomKit은 방탈출 게임 하나를 **테마**로 관리합니다. 제작자는 Studio에서 미디어와 게임 로직을 구성하고, 운영자는 세션을 시작해 진행 상황을 확인합니다. 방 안의 화면, 스피커, 키오스크와 센서는 Player 앱 또는 클라이언트 라이브러리를 통해 서버의 커맨드를 실행합니다.

## 구성 요소

```text
Studio ── REST/Socket.io ── RoomKit Server ── PostgreSQL / S3
                              │
                              ├── Player ── 웹사이트(@roomkit/helper)
                              └── 커스텀 장치(@roomkit/client)
```

- **Server**는 로그인, 애셋, 세션, 타이머와 이벤트 시퀀스를 관리합니다.
- **Studio**는 테마 제작과 실제 세션 운영에 사용하는 웹 화면입니다.
- **Player**는 방 안의 장치에서 웹사이트, 소리, 영상과 자막을 재생하는 데스크톱 앱입니다.
- **`@roomkit/helper`**는 Player 안의 웹사이트가 Player와 통신하도록 연결합니다.
- **`@roomkit/client`**는 Player 없이 독립적으로 동작하는 장치를 서버에 직접 연결합니다.

## 꼭 알아야 하는 용어

| 용어 | 의미 |
| --- | --- |
| 테마 | 방탈출 게임 한 종류입니다. 애셋과 세션은 하나의 테마에 속합니다. |
| 애셋 | 장치, 플레이어, 미디어, 웹사이트, 힌트, 페이즈, 이벤트 등 제작에 사용하는 모든 항목입니다. |
| 장치 | 화면, 스피커, 센서처럼 커맨드를 받거나 트리거를 보내는 논리적 접속 지점입니다. 고유한 장치 코드로 접속합니다. |
| 플레이어 애셋 | 오디오를 재생할 장치와 자막·영상을 보여 줄 장치를 묶은 출력 그룹입니다. Player 앱과는 다른 개념입니다. |
| 페이즈 | 게임의 진행 단계입니다. 예를 들어 `입장`, `연구실`, `탈출`처럼 나눌 수 있습니다. |
| 이벤트 | 트리거와 실행할 커맨드 목록을 묶은 게임 로직입니다. |
| 세션 | 한 팀이 테마를 플레이하는 한 번의 실행입니다. |
| 힌트 | 입력 코드, 단계별 내용과 선택적인 정답으로 구성됩니다. |

## 게임이 실행되는 과정

1. Studio에서 장치와 미디어, 페이즈, 이벤트를 제작합니다.
2. 장치가 코드로 서버에 접속합니다.
3. 운영자가 세션을 시작하면 타이머와 `session:start` 이벤트가 시작됩니다.
4. 장치가 트리거를 보내거나 운영자가 이벤트를 실행하면 서버가 시퀀스를 처리합니다.
5. 서버가 재생, 이동, 메시지 같은 커맨드를 장치에 전송합니다.
6. 기다리도록 설정한 커맨드는 장치의 완료 응답을 받은 뒤 다음 커맨드로 진행합니다.
7. 운영자는 로그와 장치 상태를 확인하고, 게임이 끝나면 세션 결과를 확인합니다.

## 설계상 중요한 특징

- 한 서버에서 여러 테마를 관리할 수 있습니다.
- 테마 하나에는 종료되지 않은 프로덕션 세션을 하나만 만들 수 있습니다. 같은 게임을 여러 방에서 운영하려면 테마를 복제해 주세요.
- 테스트 세션은 여러 개를 동시에 실행할 수 있습니다.
- 파일이 준비되지 않아도 재생 시간을 지정한 플레이스홀더 미디어로 로직을 먼저 테스트할 수 있습니다.
- 커맨드는 적어도 한 번 전달될 수 있으므로 클라이언트는 커맨드 ID로 중복을 제거합니다.
- 오프라인 장치로 보낸 커맨드는 실패로 기록하고 다음 커맨드로 진행합니다.
